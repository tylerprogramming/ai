# Apify actors: verified calls, real output fields, known gotchas

Everything here was run against the live Apify MCP on 2026-08-29, on the topics "claude code" and
"claude code skills / subagents". Field names are copied from actual dataset output, not from docs.

**Tool names shift between sessions.** Some sessions expose dedicated tools
(`mcp__claude_ai_Apify__streamers--youtube-scraper`), others only expose `call-actor`. The actor
full names below always work through `call-actor`, so prefer that and you never have to care:
`streamers/youtube-scraper`, `clockworks/tiktok-scraper`, `apify/instagram-scraper`,
`apidojo/tweet-scraper`.

---

## YouTube - `mcp__claude_ai_Apify__streamers--youtube-scraper`

```json
{ "searchQueries": ["<topic>"], "maxResults": 25, "sortingOrder": "views",
  "dateFilter": "month", "waitSecs": 45 }
```

- `sortingOrder`: `relevance | rating | date | views`. Use `views` for the leaderboard.
- `dateFilter`: `hour | today | week | month | year` (this is the window control). There is **no
  3-month option**, and `oldestPostDate` forces sorting to NEWEST, which kills the view ranking. So
  a "last 3 months" request becomes `month` on YouTube. Say that in the brief's scope line.
- Shorts: add `"maxResultsShorts": 20`. `maxResults` alone returns long-form only.
- Transcripts (verified 2026-08-29, this is the path that works):
  ```json
  { "startUrls": [{"url": "<video url>"}, ...], "downloadSubtitles": true,
    "subtitlesFormat": "plaintext", "subtitlesLanguage": "en",
    "preferAutoGeneratedSubtitles": true, "saveSubsToKVS": false }
  ```
  Each item comes back with `subtitles: [{srtUrl, type, language, plaintext}]`, where `type` is
  `auto_generated` or `user_generated`. Take the first entry with a non-empty `plaintext`.
  Pass all 3 videos as `startUrls` in ONE run. Do not set `maxResults` on a startUrls run - the
  status line can report 1 item while the dataset actually holds all of them; download the dataset
  and count there. Local yt-dlp was returning `YTDLP_FAILED` on every video that day
  ("The page needs to be reloaded"), so budget for this route.
- The run often returns `status: READY` (still starting). Poll `get-actor-run` with the runId,
  then `get-dataset-items`.

Output fields: `title, url, viewCount, likes, commentsCount, channelName, channelUsername,
numberOfSubscribers, date, duration ("00:12:42"), type, id, text (description), subtitles`

## TikTok - `mcp__claude_ai_Apify__clockworks--tiktok-scraper`

```json
{ "searchQueries": ["<topic>"], "resultsPerPage": 25, "searchSection": "/video",
  "videoSearchSorting": "MOST_LIKED", "videoSearchDateFilter": "LAST_3_MONTHS", "waitSecs": 45 }
```

- `searchSection: "/video"` is required for `videoSearchSorting` / `videoSearchDateFilter`
  to apply. Both of those are **charged** filters.
- Hashtag route instead of search: `{"hashtags": ["claudecode"], "resultsPerPage": 25}`.
- Transcripts: `"downloadSubtitlesOptions": "DOWNLOAD_SUBTITLES"` (charged per video).

Output fields: `text, webVideoUrl, playCount, diggCount, commentCount, shareCount, collectCount,
createTimeISO, authorMeta.name, authorMeta.fans, videoMeta.duration, hashtags`

## Instagram - `mcp__claude_ai_Apify__apify--instagram-scraper`

**Gotcha, verified:** `{"search": "claudecode", "searchType": "hashtag"}` returned a single
`{"error": "no_items", "errorDescription": "Empty or private data for provided input"}`.
Use `directUrls` instead:

```json
{ "directUrls": ["https://www.instagram.com/explore/tags/<tag>/"],
  "resultsType": "posts", "resultsLimit": 30, "waitSecs": 45 }
```

**Second gotcha:** that hashtag feed is the **recency** feed, not the top feed. The 8 posts it
returned were all minutes old with 0-2 likes. So:

- Use the hashtag pull for **format, caption, hook and CTA patterns, and who is posting** -
  never as a reach leaderboard.

**Third gotcha, verified:** there is no reach on Instagram at all on this account tier.
`videoViewCount` came back **null on every post, including a `clips` item**, and `productType` was
null on 11 of 12. Do not promise plays.

What you can get is followers, which turns raw engagement into a comparable rate. One `details`
call per batch of handles returns both halves:

```json
{ "directUrls": ["https://www.instagram.com/<handle>/", "..."],
  "resultsType": "details", "resultsLimit": 12 }
```

Returns `followersCount`, `postsCount`, and `latestPosts[]` with `likesCount`, `commentsCount`,
`timestamp`, `caption`, `url`. Six handles in one run took 34s. Feed that file to
`rank.py --profiles` and it ranks Instagram on **engagement per follower**.

Why it matters: in the 2026-08-29 pull the top Instagram post by raw engagement was `bestapps.ai`
with 72, on **198,402 followers** (0.04%). `oneto.code` had 11 engagements on **26 followers**
(42.31%). Raw engagement had the ranking exactly backwards.

**`likesCount: -1` means likes are hidden**, not zero. `rank.py` maps negatives to `n/a`.

Output fields: `caption, url, likesCount, commentsCount, videoPlayCount, videoViewCount,
videoDuration, ownerUsername, timestamp, type (Image|Video|Sidecar), productType (clips|feed|
carousel_container), hashtags, firstComment`
Carousels report no play count and likes are sometimes hidden - `rank.py` ranks those by
engagement in a second table rather than dropping them.

## X - `mcp__claude_ai_Apify__call-actor` with `apidojo/tweet-scraper`

```json
{ "actor": "apidojo/tweet-scraper",
  "input": { "searchTerms": ["<topic>"], "maxItems": 25, "sort": "Top",
             "tweetLanguage": "en", "minimumRetweets": 0 },
  "waitSecs": 45 }
```

- `sort`: `Top` or `Latest`. Window: `start` / `end` as `YYYY-MM-DD`.
- Pay-per-result, ~$0.0004/tweet, so `maxItems` is the cost dial.

Output fields: `text, fullText, url, viewCount, likeCount, retweetCount, replyCount,
bookmarkCount, quoteCount, createdAt ("Sat Aug 29 14:26:00 +0000 2026"), author.userName,
author.followers, isReply, isRetweet`

## Getting the data onto disk

**Do this, not `get-dataset-items`.** Apify dataset items are readable over plain HTTP by dataset
id with **no token**, so curl the whole thing straight to a file. Full fidelity, nothing
transcribed by hand, no context burned (verified 2026-08-29, HTTP 200 on a fresh private run):

```bash
curl -s "https://api.apify.com/v2/datasets/<datasetId>/items?format=json&clean=true" \
  -o raw-<platform>.json
```

The datasetId is in the `call-actor` result under `storages.datasets.default.id`.

Use the MCP `get-dataset-items` only when you need to eyeball a few rows. It returns **flattened**
keys (`"authorMeta.name"`) when you pass `fields=`, while the curl dump is nested. `rank.py`
handles both.

Always project only what the brief needs:

| platform | fields |
|---|---|
| youtube | `title,url,viewCount,likes,commentsCount,channelName,numberOfSubscribers,date,duration,type` |
| tiktok | `text,webVideoUrl,playCount,diggCount,commentCount,shareCount,createTimeISO,authorMeta.name,authorMeta.fans,videoMeta.duration` |
| instagram | `caption,url,likesCount,commentsCount,videoPlayCount,videoViewCount,ownerUsername,timestamp,productType,type,videoDuration` |
| x | `text,url,viewCount,likeCount,retweetCount,replyCount,createdAt,author.userName,author.followers` |

## YouTube comments - `streamers/youtube-comments-scraper` (via `call-actor`)

The main YouTube actor **cannot scrape comments** - its input schema has no such field. This is a
separate actor, same developer, official Apify, 22.4K users, 4.89 stars, $0.0015 per comment.

```json
{ "startUrls": [{"url": "<video url>"}, ...], "maxComments": 100,
  "sortCommentsBy": "NEWEST_FIRST" }
```

- `sortCommentsBy` takes **`TOP_COMMENTS` or `NEWEST_FIRST` only**. `"top"` fails input validation.
- `maxComments` is **per video** (60 x 2 videos returned 120) and **defaults to 1**. Always set it.
- Run it twice: `TOP_COMMENTS` at 25 for the reaction pass, `NEWEST_FIRST` at 100 for demand.

Output fields: `comment, author, voteCount, replyCount, publishedTimeText, authorIsChannelOwner,
hasCreatorHeart, replyToCid, cid, videoId, title, commentsCount` (that last one is the video's
total, useful for saying "9 of 219").

**Why two passes** (measured on a 219-comment video): 3 of 25 top comments contained a question,
against 31% of the newest ones. Top comments are praise, jokes and the creator's own pinned link.

## TikTok comments - same `clockworks/tiktok-scraper`, separate dataset

```json
{ "postURLs": ["<video url>"], "resultsPerPage": 1,
  "topLevelCommentsPerPost": 25, "commentsPerPost": 25 }
```

**Gotcha:** the comments do **not** land in the run's default dataset. That dataset holds the video
item, and the comments are in a second dataset whose URL is in the item's `commentsDatasetUrl`
field. Read that field, then curl that URL.

Comment fields: `text, uniqueId, uid, diggCount, replyCommentTotal, repliesToId, cid,
createTimeISO, videoWebUrl, pinnedByAuthor, likedByAuthor`.

Note this is a second run against specific `postURLs`. Setting `commentsPerPost` on the original
search run would pull comments for all 26 items, not just the winners.
